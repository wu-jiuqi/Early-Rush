# v3 果冻冲撞：设计与实现核对

范围：独立 `EarlyRushUnityV3/`，保留 v2 源码、包和报告。本文来自当前 C# 源码的只读核对，记录实现意图与参数，不是运行结果。后续修复或调参后应再次核对；最终通过数、性能与截图检查见 v3-validation.md；包校验见发行清单。

## 行为变化

普通接触采用轻推与小幅形变；Space 冲刺命中后把通勤者撞飞、翻转和短暂击倒，产生有上限的连锁，再让 NPC 回到向前通勤路线。玩家可用强冲撞制造局部空隙；Shift 保留抗推与精细调整用途，但取消冲刺并减速。

本版不再沿用 v2“碰到人流便触发玩家自身失衡”的旧接触路径。游戏依旧保留墙体、边界、共享 110 秒计时、三段流程、超时继续和大地图镜头。果冻形变仅作用于视觉节点，不改变玩家或 NPC 的平面碰撞半径。

## 处理流程

1. 普通接触使用圆形角色与静态障碍的分离逻辑，限制 NPC 推挤速度。
2. 每次 Space 冲刺获得独立编号，利用该物理步的玩家移动线段检测命中，避免只检测终点而漏碰。
3. 命中方向混合玩家前进方向与目标外推方向，给目标有限的水平速度和竖直表现速度。
4. 飞行期间仍使用平面移动与障碍解析；水平速度衰减，碰墙去除主要入墙分量。竖直高度与翻转属于自定义卡通表现，不是完整 3D 刚体模拟。
5. 空中目标可沿运动线段触发次级连锁，但每次冲刺的目标集合去重，人数和传播深度均有上限。
6. 落地清空飞行动量；恢复期间就参加 NPC 间的渐进分离，仍不阻挡玩家。恢复完成后重新接回不倒退的通勤路径，避免多人同时恢复碰撞时才开始解开重叠。

## 果冻与镜头反馈

`RushVisuals.ImpactScale` 分为压缩、拉伸和阻尼回弹三个阶段；落地额外叠加压缩脉冲。模型围绕身体支点翻转与回弹，物理根节点保持单位缩放。普通接触使用较小强度，直接撞飞使用较强形变，连锁略减弱。

`RushImpactFx` 使用项目已有几何体和材质生成冲击环、星形闪光与落地效果，生命周期由游戏主动推进。主菜单和暂停菜单提供独立震屏按钮；关闭后只移除镜头冲击位移，不关闭跟随、形变或音效。震屏没有单独键盘快捷键。

## 暂停与重置

- 进入暂停先清理短暂撞击效果、震动、停顿和形变瞬态，随后不推进玩家、NPC 飞行或通勤计时。暂停前后的状态比较应从暂停清理完成后取样。
- 恢复后必须松开旧 Space / Shift 才能重新触发动作，避免旧按键跨状态重复攻击。
- 重开、换关与返回菜单清理场景冲撞状态；NPC 回收时重置飞行、落地与形变状态。
- 震屏开关与声音开关独立；当前没有据此承诺跨应用启动保存偏好。

## 验收分层

`--qa` 运行普通三段通勤路线，继续检查共享计时、风险/绕行、迟到、镜头、边界、暂停和重开。该路线不能用传送或直接完成关卡代替实际移动。

`--impact-qa` 启用专门的正面、侧面、连锁和边界测试布置。`SetupImpactFixture` 只在该命令行模式下允许初始化；它会设置测试起点与目标排列。初始化后的撞击仍由 QAMove / QADash / QABrace 输入触发，不能把这类受控场景写成未经布置的完整通勤实测。

局部验收应核对：普通轻推与冲刺差异、目标起飞/翻转/落地、真实二级连锁、单次最多 6 人与同目标不重复触发、碰墙与边界、落地重返路线、根节点尺度、震屏关闭、停顿/飞行/落地期间暂停以及重开清理。截图用于确认玩家、NPC 和反馈可辨认；参数断言不能替代视觉检查。

两类测试均运行于实际 Windows Player 时，才能称为 Player 输入驱动测试；它们不等于系统键盘自动化或真人手感验证。最终运行结果见 v3-validation.md。
