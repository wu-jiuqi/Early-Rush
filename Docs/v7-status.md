# Early Rush v7 · 美术与通勤机制改版

## 基线与当前状态

基于 `release/v6-journey` 的 `18b004f`，不是 `main` 或错误指向 V4 的 `v0.6.0-prototype` 标签。旧分支、标签、Release 不覆盖。

当前为待 Unity 验收的源码版本。已有 image_gen PNG 资产、源码接入和静态/数学模型验证；**尚未完成 Unity 编译、Windows Player 运行、实际场景截图和性能测试，不是可交付 EXE**。构建机器离线时不会生成假的构建收据、复用 V6 报告或提前发布完成声明。

## 本轮实现

- 按参考图使用薄荷青、奶油白、暖黄的圆润2.5D栅格美术。生成角色、骑车、场景物件、UI、任务、地面5张图集，实际图片及生成记录随源码保存。
- 角色采用图集视角，保留原碰撞/击飞根节点及压缩回弹；主角前后左右视角，NPC当前使用背影变体。不是完整骨骼/逐帧角色动画。
- 主要桌椅、站亭、售票机、闸机、植物、栏杆、纸箱、打卡机等接入图片。碰撞体和导航路径不依赖图片变化。
- UI以图片按钮、路线图标、数字计时及进度为主。第一次操作说明、按键提示、悬停解释保留少量文字；世界招牌改图标。
- `E` 独立交互：靠近终点按住自动制动并打卡，避免边走边按 Shift 导致速度超过阈值、进度清零。静止 Shift 兼容原操作回归。
- 早餐、失物、咖啡为可选两站取送任务，以物品气泡呈现。完成各增加8秒截止宽限，不修改实际通勤用时。
- 第二街区雨天视觉/转向惯性；站厅左楼梯减速、右扶梯向前传送。它们是平面玩法区，不是实际3D楼层高度系统。
- 保留原有宽窄、弯折、主路/绕行路线，未把少量修改夸大为全新关卡设计。

## 明确的美术边界

已替换主要角色、交互物和界面图标，**不是每一个可见网格都已移除**。地面标线、碰撞危险区、地图基座、建筑边界、进度条、阴影底板和雨丝等仍是功能性程序绘制/几何，不是SVG占位。新增sprite与3D碰撞轮廓、深度排序、漂浮遮挡需在Unity中逐段检视；不把资产预览当运行截图。

图集行列采用实际图片尺寸切分，不假定1024/2048。导入禁用NPOT自动缩放与有损压缩，保留alpha。透明图低alpha隐RGB在真实背景合成检查正常。静态地面共享材质，运行时地面网格切关主动释放。

## 恢复构建后的顺序

1. 用 Unity 6000.0.26f1 打开此工程，检查 Console；执行 Early Rush/Validate v7 Art。
2. `powershell -File Tools/build_v7.ps1 -Unity D:\unity\Editor\Unity.exe`。独立输出 `../artifacts/EarlyRush-V7-Windows`，不覆盖V6。
3. 运行可见 Player 的 `--journey-qa`、`--combat-qa`、`--impact-qa`，输出到独立v7目录。新的risk路线已加入 E+持续前进打卡，其他路线仍检查Shift兼容。
4. 人工检查三关、多分辨率、人物边缘、场景深度/碰撞一致、菜单按钮、任务取送/重复领取/切关清理、楼梯/扶梯方向、雨天辨识度、按住E切后台。
5. 性能采样只引用本次Profiler/Player数据，不从精灵替换或网格数量推定改善。
6. 冻结最终源码/二进制哈希，封装完整EXE+Data+DLL。新建独立Release，上传后下载校验，才能标记完成。

竞赛20MB限制若仍适用，Unity完整Windows包很可能超限。必须量测实际包，不能删除必要运行库来凑大小；比赛提交渠道/压缩限制需单独确认，当前未代用户提交比赛。
