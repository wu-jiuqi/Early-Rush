# Early Rush 美术素材清单与接入规范 v1

日期：2026-11-11。依据：三阶段关卡设计方案 v3；当前源码 `5806d31`；本轮用户新增的空格冲刺、Shift 稳步抗冲撞、路人主动冲撞及更丰富人流。本文仅交付制作要求，尚未实现这些新增程序机制。

建议制作路线是：先完成可替换的静态素材，验证比例和接地点；再制作四方向角色动作与任务动效；最后扩充人群变体和环境事件。分帧 PNG 与可编辑源文件作为母版，图集交给程序统一生成。

配套文件：`EarlyRush-美术生产清单-v1.csv`。每行代表一项素材包或动作包，不等于一张图片；实例数量、方向数、状态数、帧数分开记录，避免把两个轮子算成两套美术。

## 1 范围与状态标记

| 标记 | 含义 | 能否放入项目直接生效 |
| --- | --- | --- |
| A 直接替换 | 当前代码已经读取的完整资源键 | 可以，需满足画布、接地点和比例要求，重新运行后加载 |
| B 接口扩展 | 需求明确，当前没有对应独立资源键或播放接口 | 不可以，需程序增加映射、分层或播放器 |
| C 方案待定 | 影响最终制作量的规则细节未确定 | 先做分层源稿/样张，不批量做最终动作 |

CSV优先级是制作顺序：P0为玩法辨识必需，P1为完整动作与人流扩展，P2为氛围与装饰。它不等同策划中P0–P4研发批次。

冲刺、稳步和路人主动冲撞是本轮已提出的新增需求，必须纳入清单。v3曾约束“无撞击眩晕”；击退距离、腾空幅度、恢复期间能否操作，以及骑行时Shift表现尚未确定。美术先把受击、腾空、落地、恢复分开，动画不得自行决定控制锁定。

## 2 统一画面要求

- 采用接近正俯视的2.5D精灵表现，圆润简洁，奶油白地面、青绿主体、明黄标线、柔和阴影。可用珊瑚橙突出玩家；人群避免大面积使用同等强度的玩家强调色。
- 当前实际工程是XY平面精灵与Tilemap，摄像机正交、固定北向。美术中的体积和俯视关系画在图片里。不要按旧X/Z工程重新旋转模型，也不要交一套菱形等距地砖。
- 先交一张比例标定图：人物、车轮、椅子、抹布、桌子、门口同框。建议先试约75°高俯视的视觉效果，角度仅为美术样张起点，三场景与所有方向统一后再量产。
- 光源固定左上，软阴影偏右下；阴影尽量单独成层。不要让人物转向时光源跟着转。左右镜像仅在衣物、包、杯子和受光都允许时使用，持杯角色通常需分别画左右。
- 人物脚底、轮子接地中点、家具地面投影必须清楚。人物身体允许遮挡，但玩家定位标记不能被高家具彻底盖住。
- 环境对比低于交互物；任务物比装饰更清晰。可推椅子/轮子/抹布用轮廓与材质区分，不能只依赖颜色。
- 路口、物件回推空间、下客通道、文件工位和早会入口必须留白。背景不得画出不存在的入口，也不能把可走区域画成实墙。
- 不把路人、任务道具、标记、文字、碰撞框和地面合成整张场景大图；按可独立移动、遮挡和改变状态的对象拆件。

## 4 静态图尺寸与接地点

以下像素尺寸为推荐交付规格，不是策划硬数值。统一先按1280×720游戏窗口检查，再检查1920×1080与960×540。不能为了高分辨率，把路人全部做成2K单帧。

| 类型 | 推荐输出画布 | 要点 |
| --- | --- | --- |
| 人物动作帧 | 256×384，四向与同角色所有动作统一 | 包含受击/蓄力姿态的最大范围；禁逐帧自动裁边 |
| 骑行合成帧 | 384×384 | 身体、车、脚踏、车轮在源稿拆层；四向总画布一致 |
| 轮子/椅子/抹布/杯子/文件 | 256×256，细长物按实际比例 | 不强行塞成正方形视觉；检查完整画布缩放后的实际占地 |
| 店铺/固定机台/工位 | 通常512×512；宽物512×256 | 比例服从场景宽度，边缘保留透明安全区 |
| 列车/长柜台/会议桌 | 1024×512或1024×256 | 门叶独立；不把整段站台画入列车图 |
| 地面纹理 | 512×512 | 当前一张图按4×4切成16块，整张覆盖4×4世界单位；宽高均可被4整除 |
| 路缘/导向带 | 512×64或512×128 | 必须保留长条比例，不能用正方形贴图替代 |
| 图标/头像 | 128×128；极少数大展示256×256 | 24px地图标记、32px提示、48px任务槽都做缩略检查 |
| 小特效 | 128×128或256×256每帧 | 尽量短时、透明占地小，不把全屏透明区域塞进每帧 |

当前世界物使用完整PNG画布创建Sprite，再按目标世界宽度统一缩放。透明留白会参与宽度计算，因此“图片宽512像素”并不能保证物体看起来一样大。同类素材主体占画布的比例应一致，建议横向占70%–85%，先用样张验证。

当前一般接地点是归一化`(0.5, 0.1)`，坐标从图片左下角起算。例：256×384人物，双脚之间的地面点放在约`(128, 38.4)`像素处，角色向上伸展。宽度1.05单位时，若不裁边，比例约为1.05/256单位每像素。

现有特殊接地点必须单独处理：`tasks/chair`是`(0.492,0.055)`，256×256约为`(126,14)`；旧`tasks/backpack`是`(0.5,0.04)`。新素材如果需要不同接地点，提供元数据并由程序接入，不能只在Unity Sprite Editor里改，因为当前运行时会重新创建Sprite。地面Tile使用中心点`(0.5,0.5)`。

平面贴花、水渍、收纳框适合地面中心锚点；现代码大部分仍走通用0.1锚点。清单中新增地面资源应一并建立独立中心锚点映射，避免为了兼容0.1把大半张图藏到画布外。

人物物理半径当前0.46单位，轮子/椅子0.55，抹布0.7。人物显示宽约1.05，骑行1.3，轮椅约1.21，抹布约1.54；这些只是当前灰盒校对值。PNG轮廓不会自动生成碰撞体，修改图片不能暗改这些规则。

## 5 角色序列帧清单

以下帧数与播放速度是首轮制作预算，需样张试玩后定稿。均为每个方向的帧数；四方向`up/down/left/right`，不要求先制作8方向。斜向输入继续选择主方向。

| 对象/动作 | 建议帧数×方向 | 循环/播放建议 | 必须分开的信息 |
| --- | --- | --- | --- |
| 玩家站立 | 1–2×4 | 1帧即可；呼吸可补间 | 稳定脚底与朝向 |
| 玩家走路 | 6×4 | 10–12fps循环，播放速率随实际移动速度 | 左右脚接触节奏，停止后立即回待机 |
| 玩家冲刺 | 4×4 | 12–16fps，可复用中间循环段 | 起势/持续/结束，残影单独做 |
| Shift稳步待机 | 2×4 | 低重心循环或2帧混合 | 与普通待机形状可辨，不靠“隐身”表达 |
| Shift稳步移动 | 4×4 | 6–8fps短步循环 | 脚底仍跟实际位移，不在原地滑步 |
| 稳步抗撞成功 | 2×4 | 一次性，建议0.12–0.2秒视觉反馈 | 躯干压缩/小火花；物理是否位移由程序决定 |
| 玩家受击 | 3×4 | 一次性约0.15–0.25秒 | 受击方向与朝向独立，勿烘焙世界坐标位移 |
| 玩家腾空 | 1–2×4 | 持续时间由模拟控制 | 身体层和地面阴影分开；不能把阴影一起抛高 |
| 玩家落地/恢复 | 3×4 | 一次性约0.18–0.3秒 | 落地时刻由模拟事件触发，能否操作由玩法规则决定 |
| 骑行待机/骑行 | 1×4 / 4×4 | 骑行8–12fps；车轮最好独立旋转 | 不把朝向切换做成镜头旋转 |
| 骑行冲刺/稳步 | 先复用骑行+姿态补间 | 已列需求，具体表现待规则确定 | Shift是刹车稳车还是下车，先不额外批量画整套 |
| 普通路人站立/走路 | 1×4 / 6×4 | 可共用节奏和换色模板 | 同屏角色错开动画相位 |
| 冲撞路人蓄力 | 3×4 | 末帧可保持，视觉按蓄力进度采样 | 肩部/重心/腿部方向，不用仅一闪红色 |
| 冲撞路人冲出 | 3×4 | 中段可保持或循环 | 方向固定的发力姿态，位移完全由模拟驱动 |
| 冲撞取消 | 2×4 | 一次性 | 取消要迅速撤掉方向提示，不播放“命中”效果 |
| 冲撞后恢复 | 3×4 | 一次性，时长可拉伸 | 未命中与命中都能进入恢复；没有假命中 |
| 持咖啡行走 | 6×4，优先身体复用 | 杯子/手臂覆盖层与基础步态同步 | 握杯位置；上下方向都看得见杯子 |
| 下车/赴会行走 | 复用普通走路 | 通过路线和速度表达，非新增整套动作 | 下客不加M1专属警示 |

严格按最低帧数计算，玩家站立、走路、冲刺、稳步待机、稳步移动、抗撞、受击、腾空、落地、骑行待机/骑行合计约124张分帧PNG，**不含新增皮肤、骑行专属冲刺/稳步和独立配件**。这是制作预算示例，不是已审批外包数量。先做1方向样张和4向走路验收，再扩到全动作。

### 序列帧交付约定

1. PNG RGBA，透明背景，标准直通Alpha。无白底、棋盘格、外围白边、画布内帧号、logo。分层源稿保留，预览GIF/MP4只作审片，不作为运行资源。
2. 同一角色所有动作统一画布、绘制比例和接地点；关闭逐帧trim。允许角色上身变化，地面根点不能在序列里左右游走。脚步动作不等于Root Motion。
3. 动画原地制作；移动、冲刺距离、腾空轨迹、真实碰撞由程序决定。循环不要重复输出末尾第一帧造成停顿。
4. 每个动作提供帧列表、建议fps、是否循环、可循环段、进出姿态、可被哪些状态中断、手持物挂点、关键视觉时刻。脚步等事件仅供声音/视觉，不用于结算任务或判定命中。
5. 蓄力/列车门/扭蛋灯等应按逻辑进度采样，不以固定动画总时长支配游戏规则。暂停时帧和补间一起停；恢复不补跳后台帧。
6. 多人共用材质与帧资源。不要为每个NPC生成一份相同Texture或独立播放材质；换装需要统一图层与挂点，当前分层系统待接入。

建议命名：`player/walk/down/000.png`、`player/brace-walk/right/003.png`、`crowd/commuter-a/windup/up/002.png`。这是**拟新增格式**，当前代码不会自动读取这些目录。

元数据示例（交付约定，尚无解析器）：

```json
{
  "schema": "early-rush-animation-1",
  "assetId": "player.walk.down",
  "files": ["000.png", "001.png", "002.png", "003.png", "004.png", "005.png"],
  "canvasPx": [256, 384],
  "pivotNormalizedBottomLeft": [0.5, 0.1],
  "worldWidth": 1.05,
  "fps": 12,
  "loop": true,
  "rootMotion": false,
  "clock": "gameplay",
  "visualEvents": [{"frame": 0, "name": "foot-left"}, {"frame": 3, "name": "foot-right"}]

```

可附无裁切精灵表：按左到右、上到下排列；注明cell尺寸、行列、有效帧数；单格边缘预留2–4px，图集打包再按采样/Mipmap增加外扩。精灵表不是当前程序可直接替换的文件；尺寸不得超当前2048导入上限，否则会被缩小。角色帧较多时拆多页，不交一张超长条。

## 6 程序补间与序列帧如何分工

| 效果 | 美术交付 | 程序处理 | 禁止事项 |
| --- | --- | --- | --- |
| 翻板 | 底座、正面、反面 | 仅面片局部scaleX接近0后换面再展开，最终状态以逻辑为准 | 不翻动物理底座、不用动画事件改解题结果 |
| 扭蛋机敲击 | 机身、灯、扭蛋分层 | 机壳局部摇摆；进度控制扭蛋位移；掉落视觉事件 | 不让机身根节点漂移，不让错拍也播“成功” |
| 轮子/骑行车轮 | 轮毂与轮胎或简化运动帧 | 按已发生位移旋转，停下即停止 | 不用旋转角反推推动成功 |
| 椅子收纳 | 椅子、目标框、完成勾 | 模型稳定停留成功后短补间；逻辑占位只做一次 | 不在物件尚未达标时先吸进检查点 |
| 列车门 | 车体、门框、左右门叶、灯 | 车门阶段驱动门叶；碰撞/下客窗口由列车流程控制 | 不把开门结束当唯一任务完成条件 |
| 推挤/抗撞 | 角色原图、小冲击纹理 | Visual子节点局部压缩/倾斜，阴影在地面 | 不缩放物理根、改碰撞半径或震动镜头 |
| 腾空/落地 | 身体腾空/落地帧、独立阴影 | 逻辑高度驱动身体局部偏移与阴影大小 | 不把身体贴图偏移当真实地面位置或排序依据 |
| 文件交付/任务完成 | 文件、勾、星、少量火花 | 一次性短飞入/缩放，完成状态先由逻辑确定 | 不因动画重播重复给星 |
| 水渍变干 | 湿区Alpha/边缘素材、干地面 | 扫掠区域更新遮罩或有效单元，重叠面积去重 | 不按时间自动擦净、不让回位轨迹擦水 |
| HUD/地图提示 | 图标、轮廓、条形底 | 透明度、进度和轻缩放；界面转场可用独立UI时钟 | 不烘焙数字/倒计时/中文文案、不做M1成功弹窗 |

补间只写表现子节点，物理位置由唯一模拟逻辑写入。暂停、重试、切场景时取消旧补间与回调；重复触发时明确重启/叠加/忽略策略。位移插值与动画采样必须使用帧率无关时间。

本项目暂未指定DOTween等第三方库，也未建立通用Animator状态机。美术交PNG与层级说明即可，不必交绑定某一补间插件的工程；程序后续按性能与维护成本选择实现。

### 当前导入设置

项目的`RushArtV8Import`会自动设置：Texture Type=Default；sRGB开启；Alpha使用源图片；非地面Alpha Is Transparency开启；Bilinear；Read/Write关闭；NPOT不缩放；最大2048；暂不压缩。地面Mipmap开启、Repeat、Aniso 2；其他图Mipmap关闭、Clamp。

当前运行时用`Sprite.Create`按完整纹理创建Sprite，PPU=100，再按世界宽度缩放。因此不能只改PPU解决人物大小，也不能手改Sprite Editor来覆盖程序pivot。导入属性含义可核对[Unity 6纹理设置](https://docs.unity3d.com/6000.0/Documentation/Manual/texture-type-default.html)，运行时创建参数见[Sprite.Create](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Sprite.Create.html)。

现导入器是Default，并没有使用SpriteAtlas加载链路。Unity图集可打包的对象有Sprite、Sprite类型Texture2D或文件夹；因此后续若采用SpriteAtlas，应连导入器、加载器和动画引用一起改，不能仅把PNG丢进atlas后就认为完成优化。[Unity SpriteAtlas说明](https://docs.unity3d.com/ja/current/ScriptReference/U2D.SpriteAtlas.html)

程序缓存已加载纹理/精灵，同名替换后需要退出并重新进入Play或重启成品；不承诺运行中的热替换。保留已有`.meta`，不要反复删除重建资源GUID。新资源`.meta`由Unity生成后随源码提交。

当前构建器会重建入口场景，运行时再生成场景物件。因此不能只手动在生成场景里挂Animator就宣称完成接入；角色播放组件、资源配置或预制体实例化必须正式接入`RushPlayV9`的创建流程，才能在重新构建与切关后保留。

## 8 地面与模块拼接

- 地面是连续材质纹理，不是16张毫无关联的地块图标。当前按世界坐标周期4采样整图的4×4分块；整图四边无缝，各分块相邻也应连续。现切片无图集留白，不要在16块之间画透明缝。
- 建议一个世界单位对应地面图128像素。不要画透视缩小网格或大块独特污渍进基础循环纹理；污渍和特殊标记单独叠加。
- 直路、左转、右转、T形接口、任务房间和出口使用同一材质基准；墙角/路缘/停止线按实际比例提供水平、垂直及转角件。
- 街道沥青、人行道/路缘应容易分辨。当前边界以瓷砖着色临时代替人行道，正式人行道需新资源键与地图分区映射。
- 大物件提供可见轮廓和地面占地参考图，标出底座范围、通行侧、遮挡范围及需要淡出的上部。实际碰撞由地图/模拟定义，不能把透明空白当碰撞边界。
- 跨越角色的门楣、顶棚和高墙尽量拆后层、前层，不将整栋建筑作为必然遮住玩家的大精灵。

## 9 面向高密度人流的美术要求

人流增密不能只把同一个人复制更多次。建议先建立6种外观、统一动作模板，再增加场景组合。人数、生成节奏、冲撞频率和有效通道宽度属于下一轮程序设计，这份清单不预先承诺具体人数。

- 轮廓至少有瘦长/圆润等差异，但碰撞体仍以模拟配置为准。发型、外套、裤子和包分层；换色不要同时把皮肤、眼睛、鞋底染色。
- 区分普通可挤路人、即将主动冲撞的路人、持咖啡同事和下车乘客。前摇姿态与脚下方向共同表达冲撞，不给全部人持续画警示圈。
- 冲撞预告只用于本轮新增的主动冲撞行为；M1下客不加入任务专属箭头或危险预警。任何玩法上的复合角色标签需程序另行明确。
- 人群阴影小而软，避免叠成黑色地毯；少用大面积半透明尾迹和每人独立粒子。
- 共享帧资源并随机初始相位，避免整队同步抬脚。第一轮不要给全部外观各做独立受击大动画；普通推挤可用低幅度补间。
- 按“同屏2人/12人/24人”的样张做辨识对照，属于美术测试场景，不是最终人流上限。玩家、咖啡杯、前摇方向、主通路在小窗口下仍须可辨。
- 内存预算必须考虑帧数：256×384 RGBA32一帧约0.375MiB，384×384骑行帧约0.5625MiB。上述124张玩家帧中104张人物帧加20张骑行帧，合计约50.25MiB，不含图集留白、其他贴图和额外副本；4方向6帧的NPC基础步态约9MiB/完整独立皮肤。6套完整复制约54MiB。先共享/换装，再决定压缩和图集策略，不以磁盘PNG大小代替显存估算。

## 10 交付包与验收顺序

建议交付目录：

```text
EarlyRush_Art_v001/
  source/                 # PSD/ASEPRITE/KRA等源文件，命名与导出对应
  runtime-static/V8Art/   # A类同名PNG，可映射到项目Resources/V8Art
  animation-source/      # B类分帧PNG与动作JSON，暂不直接投入Resources
  ui-source/             # 图标SVG/分层源稿及PNG导出
  metadata/              # 资源表、尺寸、pivot、挂点、版权/授权说明
  previews/              # 带网格比例图、四向接地点图、动画GIF/MP4
  CHANGELOG.md            # 本次新增/替换/删除及需程序配合事项
```

原稿、预览和未使用的动画帧不要一起塞入Resources；当前构建会包含其中资源，且加载链路不认识动画源目录。所有文件名用小写英文、数字、连字符，路径大小写保持一致。

**样张门槛**：主角四向、1个NPC四向、车轮/椅子/抹布、1张地面、1个工位头像、1段冲撞前摇，先接入灰盒查看。比例、接地点、方向和色值通过后再批量生产。

**静态接入验收**：检查alpha白边、画布比例、脚底稳定、前后遮挡、地面接缝、实际通行边界；检查替换后无意外回退占位日志。A类按现键覆盖，B类等待对应程序映射，不把“生成了PNG”记为“接入完成”。

**动作接入验收**：连续转向、走停、冲刺切稳步、受击/取消、暂停恢复、重试和场景切换；无脚底跳动、镜头抖动、缩放污染碰撞体、残留特效或旧动画回调。

**任务验收**：翻板新接触才翻；扭蛋灯与窗口一致；清洁只遮掉擦过的区域；同一咖啡杯不重复洒；文件与工位头像匹配；归位椅不再移动；M1无专属过程提醒。上述均须由程序规则验证，不能只观看动画。

**当前程序待接清单**：资源元数据/pivot表；四向序列帧播放器；独立Visual根与阴影/手持物挂点；冲刺/稳步/路人冲撞状态映射；关键任务共享资源键拆分；精确门叶、扭蛋、翻板层；水渍遮罩；独立头像和UI资源映射；图集/换装与人群性能验证。

## 11 制作顺序与尚未确定的事项

第一批：主角/普通NPC四向静帧、三种基础地面、九任务可辨静态件、时钟/地图/结果图标。第二批：主角移动与新增冲撞交互动作、特殊角色道具层、九任务核心动效。第三批：人群外观扩展、分场景装饰、随机事件、氛围细节。

需要在批量动画前确定的事项只有：冲刺与稳步在骑行时的规则；腾空/击退是否影响控制及持续时间；冲撞前摇是否可取消和实际窗口；最终样张视角与人物比例；目标最低设备及可接受同时可见人群规模。现有制作建议不把这些未决项伪装成已实现参数。

这轮未修改玩法代码。空格冲刺、Shift稳步、路人主动冲撞和人流密度设计保留为下一轮开发工作。
